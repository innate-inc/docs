---
title: "Debugging"
description: "Find out why the robot, an agent, or a skill isn't working"
---

Work from the top down. Each step rules out a layer. For logs without SSH, use the web app's [Logging page](/robots/apps#logging).

<Steps>
  <Step title="Is the stack running?">
    ```bash
    innate
    ```
    Prints the version, mode, and ROS status.
  </Step>
  <Step title="Is the hardware OK?">
    ```bash
    innate diag
    ```
    Checks servos, PCB, LiDAR, cameras, and speaker. Fix hardware failures before debugging software.
  </Step>
  <Step title="What do the logs say?">
    ```bash
    innate view
    ```
    Look for red errors and panes that keep restarting. The [node session table](/software/advanced-development#the-node-session) shows what runs where.
  </Step>
  <Step title="Does the skill work alone?">
    ```bash
    innate skill run innate-os/wave
    ```
    If the skill works by hand but not from the agent, the problem is the agent: its prompt, skill list, or inputs.
  </Step>
  <Step title="What does ROS see?">
    ```bash
    ros2 node list
    ros2 topic echo /battery_state
    ros2 doctor
    ```
    See [Interfaces](/software/ros2/interfaces) for what to look for.
  </Step>
  <Step title="Restart or rebuild">
    ```bash
    innate restart   # restart all nodes
    innate build     # rebuild and restart, after changing ROS code
    ```
  </Step>
</Steps>

Still stuck? [Get help on Discord](/robots/mars/troubleshooting#get-help).
