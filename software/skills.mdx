A skill is one thing the robot can do: drive somewhere, pick up a sock, send an email. An [agent](/software/agents) chains skills together, and you can also run them by hand.

| Type | What it is | Best for |
| --- | --- | --- |
| **Code-defined** | A Python class | Precise motions, APIs, logic, sensor processing |
| **Policy-defined** | A trained neural network or a recorded motion | Manipulation that is easier to show than to code |

Both types are called the same way, so agents and other skills don't need to know which kind they use.

## Where skills live

| Folder in `~/innate-os/workspace/` | Contents |
| --- | --- |
| `custom_skills/` | **Your skills.** Gitignored, safe from updates. |
| `innate_skills/` | Skills that ship with the OS |
| any other folder | A skill pack you dropped in |

Defining a `Skill` subclass in any `.py` file registers it. No config file needed. To use a skill in an agent or another skill, import its class. The class name in snake_case is the name the apps show, so `VictorySpin` appears as `victory_spin`. Everything reloads on save, and a file that fails to import shows up in the web app with its error.

A policy-defined skill is a folder with a `metadata.json` and a checkpoint, for example `custom_skills/pick_socks/`.

To install a skill pack stored elsewhere, symlink it into `workspace/`:

```bash
ln -s /opt/team/skills ~/innate-os/workspace/team_skills
```

## Shipped skills

Don't edit these in place, because updates overwrite them. Copy one into `custom_skills/` and rename the class.

| Skill | What it does |
| --- | --- |
| `navigate_to_position` | Drive to x, y on the map, or relative to the robot with `local_frame=True` |
| `turn_in_place` | Turn by an angle in degrees |
| `navigate_with_vision` | Drive from a plain-language instruction, like "go to the kitchen" |
| `follow_aruco` | Follow an ArUco tag |
| `pick_any_object` | Pick something up from a description, like "the white sock" |
| `open_gripper`, `close_gripper` | Release or grab |
| `arm_rest_position`, `arm_zero_position` | Fold the arm away, or send it home |
| `arm_move_to_xyz`, `arm_circle_motion`, `arm_utils` | Direct arm moves, torque, and reboot |
| `wave` | A recorded wave |
| `search_memory` | Search [spatial memory](/software/skills/code-defined-skills/spatial-memory) |
| `head_emotion` | Show an emotion with head motion |

## Run a skill manually

Running a skill by hand skips the agent. It's the fastest way to test one.

<Tabs>
  <Tab title="Web app">
    On the **Teleop** page, click **Skills** and pick one.

    <video autoPlay muted loop playsInline className="w-full rounded-xl" src="/videos/simulator/victory-spin.mp4">
      Triggering a skill from the web app's skill menu.
    </video>
  </Tab>
  <Tab title="Phone app">
    Open the **Skills** tab, pick a skill, fill in its parameters, and press **Execute**. Trained skills are also in **Home → Manual**.
  </Tab>
  <Tab title="Terminal">
    ```bash
    innate skill list                             # loaded skills and their IDs
    innate skill run local/victory_spin @spins=2
    ```

    The terminal uses skill IDs: `local/<name>` for your skills and `innate-os/<name>` for shipped ones.
  </Tab>
</Tabs>
