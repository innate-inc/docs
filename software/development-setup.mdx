Your code lives and runs on the robot. You edit it in place over SSH and it reloads on save, with nothing to build or sync.

<Tip>
  No robot? The [simulator](/simulator) runs the same `workspace/`, and everything below works the same way.
</Tip>

## Open the robot in your editor

<Steps>
  <Step title="Check SSH works">
    ```bash
    ssh jetson1@mars-the-21st.local    # password: goodbot21
    ```
    Your hostname and number are in the app under **Configuration → WiFi**. Other connection options: [Connect via SSH](/robots/mars/connecting-via-ssh).
  </Step>
  <Step title="Connect your editor">
    In Cursor, Windsurf, or VS Code with the **Remote - SSH** extension, run **Remote-SSH: Connect to Host…** from the command palette and enter `jetson1@<hostname>`.
  </Step>
  <Step title="Open the OS folder">
    Open `/home/jetson1/innate-os/`. The file tree, search, and terminal now all run on the robot.

    <Callout icon="image" color="#7569FD">
      **Image to make: Editor connected to MARS.** Screenshot of VS Code or Cursor connected over Remote SSH, with the `innate-os` folder open and `workspace/custom_skills/` expanded in the file tree.
    </Callout>
  </Step>
</Steps>

## Where things live

| Path in `~/innate-os/` | Contents |
| --- | --- |
| `workspace/custom_agents/` | **Your agents** |
| `workspace/custom_skills/` | **Your skills** |
| `workspace/inputs/` | Input devices |
| `workspace/innate_agents/`, `innate_skills/` | Shipped agents and skills. Read them, but don't edit them. |
| `config/settings.yaml` | [Tunable parameters](/software/configuration) |
| `.env` | Service key and secrets |
| `ros2_ws/src/` | ROS 2 packages |

Your two `custom_*` folders are gitignored, so updates never touch them.

## Write your first skill

Follow [Your first agent and skill](/software/your-first-agent). It takes five minutes and works the same on the robot as in the simulator.

## When changes take effect

| You edited | What to do |
| --- | --- |
| Agents, skills, or inputs in `workspace/` | Nothing. They reload on save. |
| `config/settings.yaml` or `.env` | `innate service restart` |
| ROS 2 code in `ros2_ws/src/` | `innate build` (see [Modify Innate OS](/software/advanced-development)) |

If a reload seems missed, `innate service restart` always works.

<Accordion title="Version your work with a fork">
  You don't need a fork to build agents and skills. Fork [innate-os](https://github.com/innate-inc/innate-os) when you want to version your work or change the OS itself. On the robot:

  ```bash
  cd ~ && mv innate-os innate-os-backup
  git clone https://github.com/<you>/innate-os.git
  cp innate-os-backup/.env innate-os/.env
  innate service restart
  ```

  The robot's startup service points at `~/innate-os/`, so your clone launches on boot.
</Accordion>
