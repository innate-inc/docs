---
title: "Foxglove"
description: "See cameras, LiDAR, maps, and TF from your laptop's browser"
---

[Foxglove](https://foxglove.dev) shows the robot's ROS 2 data in your browser on any OS. The simulator starts its bridge automatically. On a real robot, start it yourself.

![Foxglove connected to MARS](/images/simulator/foxglove.png)

<Steps>
  <Step title="Start the bridge">
    On the robot:

    ```bash
    innate foxglove start    # prints ws://<robot-ip>:8765
    ```
  </Step>
  <Step title="Connect">
    Open [app.foxglove.dev](https://app.foxglove.dev), choose **Open connection → Foxglove WebSocket**, and paste the printed URL.
  </Step>
  <Step title="Add panels">
    Add an **Image** panel for a camera, a **3D** panel for TF, LiDAR, and point clouds, or a **Plot** panel for numbers over time.
  </Step>
</Steps>

<Warning>
  Over Wi-Fi, use the `/mars/main_camera/remote/...` topics. Raw images and point clouds are too heavy for Wi-Fi and make every panel lag. Raw topics are fine over Ethernet or in the simulator.
</Warning>

## Useful topics

| Topic | Shows |
| --- | --- |
| `/mars/main_camera/remote/left/image_rect_color/compressed` | Head camera, throttled for Wi-Fi |
| `/mars/main_camera/left/image_rect_color/compressed` | Head camera, full rate |
| `/mars/main_camera/remote/points` | Depth point cloud, throttled |
| `/scan` | LiDAR |
| `/map` | Navigation map |
| `/odom`, `/cmd_vel` | Position and velocity commands |
| `/tf`, `/tf_static` | Coordinate frames |

## Troubleshooting

| Problem | Fix |
| --- | --- |
| Can't connect | Check `innate foxglove status`, use the IP instead of `.local`, and make sure port 8765 isn't blocked. |
| No topics | Check the nodes are running with `innate view`. |
| Laggy video | Use the `remote/` and `compressed` topics. |

On Linux with ROS 2 Humble, you can also run `rviz2` directly. It finds the robot over Zenoh without a bridge.
