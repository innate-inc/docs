One command installs everything and starts the simulator:

```bash
curl -fsSL https://link.innate.bot/sim | sh
```

It asks before it installs anything, then handles the rest — Docker, uv, the
rendering libraries, the `innate-os` checkout, and the several gigabytes of
simulator that the first start would otherwise download.

**Run it from the folder you want the simulator in.** It clones `innate-os/`
there. Already have an `innate-os` checkout? Run it from inside that one
instead — it skips the clone and sets up the copy you have.

A machine with 4 CPU cores and 8 GB of RAM is comfortable. The installer
tells you how much disk it needs — about 14 GB on a bare machine, less if you
already have Docker — before it uses any.

## Run the installer

<Tabs>
  <Tab title="macOS and Linux">
    Open a terminal, go to the folder you keep projects in, and run:

    ```bash
    curl -fsSL https://link.innate.bot/sim | sh
    ```
  </Tab>
  <Tab title="Windows">
    The simulator runs inside WSL2, Windows' built-in Linux environment. You
    need it once.

    <Steps>
      <Step title="Install WSL">
        Open **PowerShell** and run:

        ```powershell
        wsl --install -d Ubuntu
        ```

        Follow the prompts — it asks you to choose a username and password for
        Linux, and may ask you to restart Windows. When it finishes it opens
        an **Ubuntu** terminal for you. That terminal is where the simulator
        lives; open it again later from the Start menu.
      </Step>
      <Step title="Run the installer in the Ubuntu terminal">
        ```bash
        curl -fsSL https://link.innate.bot/sim | sh
        ```

        In the Ubuntu window, not PowerShell. If the prompt shows a path
        starting with `/mnt/`, run `cd ~` first: that prefix is the Windows
        drive seen from Linux, and the simulator is far too slow to run from
        there.
      </Step>
    </Steps>

  </Tab>
</Tabs>

## What it does

The installer lists its steps and waits for you to confirm before it starts:

1. Installs what is missing — Docker, uv (which runs the physics), git, and
   on Linux the OpenGL libraries.
2. Clones `innate-os`, or uses the checkout you ran it from.
3. Asks how the robot's agent should reach a cloud LLM.
4. Downloads the simulator, so the first start is a start rather than a
   download.
5. Offers to start it for you.

Anything it cannot do itself, it explains: a version of Docker that cannot run
the simulator is named, with the command that fixes it, before anything is
downloaded.

### Choosing a cloud LLM

Step 3 asks how the robot's AI agent reaches a cloud LLM. The agent loop runs
on the robot either way; the choice is only which key it thinks with:

* **Your own Gemini key** — the agent calls Google directly with a
  [Gemini API key](https://aistudio.google.com/api-keys). Everything works
  except voice: the web app's speak bar needs a service key.
* **Innate service key** — the agent reaches Gemini through Innate's proxy
  with your service key, which ships with a MARS robot. The full experience,
  including the robot's voice.
* **None** — no agent; you can still drive, navigate, and trigger skills
  manually.

Run `./innate-sim setup` inside the checkout at any time to change it.

## Start the simulator

If you did not let the installer start it:

```bash
cd innate-os
./innate-sim up
```

Then open **[https://localhost](https://localhost)** and accept the
self-signed certificate. You are looking at the robot's web app: drive with
the joystick or WASD, switch between the 3D view, the robot's cameras and the
map, trigger skills, and chat with the agent.

Leave the live dashboard in the terminal open — it shows the health of every
part, the web app address, and where your code lives. Press `q` to detach,
`Ctrl+C` to stop the simulator.

## Everyday commands

```bash
./innate-sim status         # startup checks + health snapshot
./innate-sim logs startup   # startup logs; `logs brain` for the running stack
./innate-sim sh             # shell into the container
./innate-sim down           # stop the container + world server (keeps data)
./innate-sim clean          # remove containers/volumes (keeps .env + config)
```

`./innate-sim setup` re-runs the key question and the download on an existing
checkout, without installing prerequisites — use the installer for those.

## If something goes wrong

Every error is written to tell you what to do next: missing packages come
with the install command, a wedged Docker names itself, and a Docker too old
to run the simulator is refused with the upgrade command rather than failing
halfway through. The installer's detailed output is kept in
`~/.innate-install.log`.

If you get stuck anyway, [ask on Discord](/support/contact-discord) — setup
reports from new machines are how the rough edges get fixed.
